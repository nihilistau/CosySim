1. Architectural Diagnostics & Hindsight Vision
🔴 The Current State ("Layer on Layer")
Primitive Obsession: Heavy reliance on Dict[str, Any] and raw json.dumps() across the MCP tools (engine/mcp/tools/*.py).
Defensive Anti-Patterns: Pervasive use of try ... except Exception as e: return json.dumps({"error": str(e)}) in every tool, hiding tracebacks and domain errors.
God Objects & Circular Dependencies: cosysim_server.py, comms_framework.py, and the NLM proxies have become massive dumping grounds. Circular imports were recently mitigated but the coupling remains.
Hardcoded Pipelines: comms_framework.py hardcodes 24+ interceptors into _build_default_pipeline(), making it rigid and hard to test.
🟢 The Hindsight Architecture ("How it should have been built")
Domain-Driven Design (DDD) & Pydantic: Use strong typing at the boundaries. Every MCP tool should return a Pydantic model. We serialize to JSON only at the very edge (the network layer), not inside the business logic.
Centralized Error Handling: Replace the repeated except Exception blocks with a unified @mcp_tool decorator that catches typed domain exceptions (e.g., SceneNotFoundError, CharacterStateError) and formats the JSON error response automatically, while publishing to an ErrorEvent bus.
Dependency Injection & Registry Pattern: Interceptors and Tools should self-register (e.g., via decorators) rather than being manually appended to a master list.
Service Abstraction: The massive nlm_live_proxy.py (which is thousands of lines long) should be isolated behind a clean LLMProviderProtocol.

Blueprint A: Centralized Error & Decorator Logic
File: engine/mcp/decorators.py (New File)

import logging
import json
from functools import wraps
from typing import Any, Callable
from pydantic import BaseModel

logger = logging.getLogger(__name__)

class ToolExecutionError(Exception):
    """Base exception for predictable tool failures."""
    pass

def mcp_tool(func: Callable) -> Callable:
    """
    Hindsight Refactor: 
    A unified decorator for all MCP tools. 
    1. Catches exceptions and logs them properly.
    2. Automatically converts Pydantic models or dicts to JSON strings.
    3. Standardizes the error schema.
    """
    @wraps(func)
    def wrapper(*args, **kwargs) -> str:
        try:
            result = func(*args, **kwargs)
            
            # Auto-serialize Pydantic models
            if isinstance(result, BaseModel):
                return result.model_dump_json(indent=2)
            
            # Auto-serialize standard dicts/lists
            if isinstance(result, (dict, list)):
                return json.dumps(result, indent=2)
                
            return str(result)
            
        except ToolExecutionError as e:
            logger.warning(f"Tool {func.__name__} execution failed: {e}")
            return json.dumps({"ok": False, "error": str(e)})
        except Exception as e:
            # Catch-all for unexpected errors (so the prompt doesn't crash)
            logger.exception(f"Unexpected crash in tool {func.__name__}")
            return json.dumps({"ok": False, "error": "Internal system error occurred."})
            
    return wrapper

from typing import Any, List, Optional
from pydantic import BaseModel, Field

from engine.mcp.decorators import mcp_tool, ToolExecutionError

# --- Domain Models ---

class DialogOptionsResponse(BaseModel):
    options: List[str]
    conversation_heat: int
    scene: str

class DirectiveResponse(BaseModel):
    ok: bool = True
    character_id: str
    scene: str
    directive_type: Optional[str] = None
    turns: Optional[int] = None

# --- Refactored Tools ---

@mcp_tool
def get_dialog_options(
    dialog_system: Any,
    character_id: str,
    scene_id: str,
    context_tags: Optional[List[str]] = None,
    stats: Optional[dict] = None,
    max_options: int = 4,
) -> DialogOptionsResponse:
    """Return situationally appropriate dialog/action options."""
    
    # Notice: No try/except block or json.dumps() needed anymore!
    opts = dialog_system.get_options(
        character_id, 
        scene_id,
        context_tags=context_tags or [], 
        stats=stats or {}, 
        max_options=max_options,
    )
    heat = dialog_system.get_conversation_heat(character_id, scene_id)
    
    return DialogOptionsResponse(
        options=opts, 
        conversation_heat=heat, 
        scene=scene_id
    )

Blueprint C: Decoupling Interceptors
File: engine/agents/interceptors/__init__.py (New Concept) Instead of importing 24 interceptors and appending them one by one in comms_framework.py, implement an auto-registry:

# engine/agents/interceptors/registry.py
from typing import List, Type
from engine.mcp.comms_types import InterceptorBase

_INTERCEPTOR_REGISTRY: List[Type[InterceptorBase]] = []

def register_interceptor(cls: Type[InterceptorBase]):
    """Decorator to register an interceptor."""
    _INTERCEPTOR_REGISTRY.append(cls)
    return cls

def get_all_interceptors() -> List[InterceptorBase]:
    # Sort by priority dynamically
    instances = [cls() for cls in _INTERCEPTOR_REGISTRY]
    return sorted(instances, key=lambda x: x.priority)
Note for Claude: You will need to go to files like engine/agents/interceptors/natural_mood_drift.py and add @register_interceptor above the class definition. Then, in comms_framework.py, _build_default_pipeline() simply becomes:

def _build_default_pipeline() -> InterceptorPipeline:
    pipeline = InterceptorPipeline()
    for interceptor in get_all_interceptors():
        pipeline.add(interceptor)
    return pipeline
