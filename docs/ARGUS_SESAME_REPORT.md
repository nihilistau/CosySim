## 1. Executive Summary

**Sesame AI** is a voice-first AI startup building real-time conversational AI characters delivered via WebRTC audio calls in the browser. Users sign in with Google, pick a character (Maya or Miles), and have a live voice conversation powered by server-side inference. The frontend is a React SPA (Vite build) hosted on Vercel; the backend runs on GCP (us-central1) behind Firebase Auth with Docker containers serving the agent WebSocket protocol.

| Production build number | **82** |
| Bundle size | **2.06 MB** (index-E-c2zfaB.js) |
| URL paths in bundle | **101** (vs 6 observed in HAR traffic) |

### Security Posture: Strong

The security model correctly separates concerns. **Firebase JWT** (RS256, 1-hour expiry, signed by Google) handles all backend authorization. **Statsig** feature flags are client-side UI toggles only -- they control React component rendering but do not grant API access. Server-side field protection blocks email changes, role injection, and moderation status overrides. Agent services 1-5 are behind **Google Identity-Aware Proxy (IAP)**. The only public agent endpoint is `agent-service-0`, authenticated via Firebase JWT.

## 4. WebRTC Voice Architecture

### Session Protocol Flow

```
Client                              Server (agent-service-0)
  |                                      |
  |──── WSS connect (JWT in URL) ───────>|
  |<──── initialize (session_id) ────────|
  |                                      |
  |──── client_location_state ──────────>|
  |     (lat, lon, address, timezone)    |
  |                                      |
  |<──── webrtc_config (ICE servers) ────|
  |                                      |
  |──── call_connect ───────────────────>|
  |     (sample_rate, codec, settings)   |
  |<──── call_connect_response (call_id)─|
  |                                      |
  |──── webrtc_sdp_offer ──────────────->|
  |<──── webrtc_sdp_answer ──────────────|
  |                                      |
  |<──> webrtc_ice_candidate (both) ─────|
  |                                      |
  |──── [audio stream via WebRTC] ──────>|
  |<──── [audio stream via WebRTC] ──────|
  |                                      |
  |──── ping (~500ms interval) ─────────>|
  |<──── ping_response ──────────────────|
  |                                      |
  |──── call_disconnect ────────────────>|
  |<──── call_disconnect_response ───────|
```

### WebSocket Message Types (13 total)

**Client to Server (6):**

| Message Type | Fields | Notes |
|-------------|--------|-------|
| `client_location_state` | latitude, longitude, address, timezone | Sent after initialize |
| `webrtc_sdp_offer` | sdp, sample_rate | WebRTC SDP offer |
| `webrtc_ice_candidate` | sdp, sdp_mid, sdp_m_line_index | ICE candidate exchange |
| `call_connect` | sample_rate, audio_codec, reconnect, is_private, settings, client_name, client_metadata | Initiates voice call |

## 12. Security Assessment

| # | Finding | Severity | Description | Mitigation |
|---|---------|----------|-------------|------------|
| 1 | **JWT in WebSocket URL** | Medium | Firebase JWT passed as `?id_token=` query parameter. Appears in server logs, browser history, CDN logs, and Referrer headers. | Move to WebSocket subprotocol or first-frame auth. |
| 2 | **Public GCS bucket (dev naming)** | Low | `sesame-dev-public` is publicly readable. "dev" naming in production suggests unmigrated early bucket. May contain unintended objects. | Audit bucket contents; migrate to production-named bucket. |
| 3 | **No visible rate limiting** | Low | Zero 429 responses across 318 HAR entries. No `X-RateLimit-*` or `Retry-After` headers observed. | Implement rate limiting headers for visibility. |
| 4 | **Statsig gate enumeration** | Info | Client SDK key allows enumerating all 27 feature gates for any email. Reveals employee-only features and rollout percentages. | Accepted risk -- Statsig is UI-only, not an auth boundary. |
| 5 | **Sequential call IDs** | Info | Call IDs are sequential integers (e.g., 23166670). Predictable, potentially enumerable. | UUIDs would prevent enumeration. |
| 6 | **CI/CD path leak** | Info | GitHub Actions runner path exposed in bundle: `/home/runner/_work/sesame/sesame/sesame/web/consumer-app`. Reveals monorepo structure. | Strip source paths from production builds. |
| 7 | **Client log email/name swap** | Low | In uploaded client logs, `email` and `displayName` fields are swapped (bug). | Fix field mapping in client logging code. |
| 8 | **Staff flag client-side** | Info | `isStaff` flag visible in client log context. Not exploitable (server-side only), but reveals role system. | N/A -- informational only. |
| 9 | **Firebase JWT forgery** | None | RS256 signed by Google. Cannot be forged without Google's private key. 1-hour expiry limits replay window. | Strong -- no action needed. |
| 10 | **Email change via API** | None | Server ignores `email` field in PUT /api/user. Properly protected. | Strong -- no action needed. |
| 11 | **Role injection via API** | None | Server ignores `roles` field in PUT /api/user. Properly protected. | Strong -- no action needed. |
| 12 | **Moderation bypass** | None | Server ignores `moderation_status` field in PUT /api/user. | Strong -- no action needed. |
| 13 | **Agent service IAP** | None | Services 1-5 behind Google IAP. Firebase JWT insufficient. Only service-0 is public. | Strong separation of internal/external. |
| 14 | **Statsig gate override** | None | localStorage cache manipulation affects React rendering only. Backend validates Firebase JWT, not Statsig state. | Correct architecture -- flags are UI-only. |

### Security Verdict

Sesame's security posture is **strong for an early-stage startup**. The architecture correctly separates:
- **Authentication** (Firebase JWT, RS256, Google-signed) from **feature flags** (Statsig, client-only UI rendering)
- **Public endpoints** (service-0 with JWT) from **internal endpoints** (services 1-5 behind Google IAP)
- **Writable fields** (nickname, birthday, preferences) from **protected fields** (email, roles, moderation)

The only meaningful concern is the JWT-in-URL pattern for WebSocket auth, which is a common trade-off in WebSocket architectures but creates unnecessary token exposure in logs.
